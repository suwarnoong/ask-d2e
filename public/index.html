✦ What it does

Everything you need to trust the answer

ask-d2e is a focused assistant: it answers from your team's knowledge bases, shows its work, and keeps that knowledge fresh.

Grounded & cited

Every answer is drawn only from a knowledge base and ends with the source page it used — no invented details.

Three ways to ask

A /ask slash command, an @ask-d2e mention, or a direct message — whatever fits the moment.

Follow-up aware

Reply in the same thread — no need to tag it again — and it remembers the conversation for coherent multi-turn answers.

One bot, every repo

ask-d2e draws on every knowledge base your team has configured, not just one codebase — same familiar /ask and @ask-d2e, more it knows.

Powered by AI

Runs on a state-of-the-art AI model that retrieves just the pages relevant to your question from the knowledge base, then answers from them.

Self-improving base

When it doesn't know something, it checks the real source itself before giving up — and anyone can flag a wrong answer with 👎, which sends it to an admin who can trigger a knowledge-base fix in one click. Each configured repo also refreshes itself on its own schedule as code changes.

✦ Honest by design

What it won't do

Transparency is the point. Here's exactly where ask-d2e draws the line — so you always know what you're getting.

  • Knowledge-base only. If a topic isn't covered, it says so honestly rather than guessing — then checks the real source itself and updates the base if it finds a real answer. No hallucinated answers, either way.
  • Only covers configured repos. If a codebase hasn't been set up yet, ask-d2e won't know about it — that's decided by your workspace admins.
  • Slack only. There's no general-purpose web chat — this page is a landing page, not the bot. You ask it from inside Slack.
  • Anyone can flag an answer, admins approve the fix. Everyone gets the 👍 / 👎 buttons — a 👎 sends the question to admins, who decide whether to trigger a knowledge-base refresh, so edits stay controlled.
  • As fresh as the last refresh. Each repo refreshes on its own schedule (daily or weekly); a 👎 correction lands right away, but everything goes live after a redeploy.
  • Occasionally busy. Under heavy AI-service load it retries automatically, then asks you to try again in a moment rather than failing silently.
